# 窓 2.0 秒のほうが 1.0 秒より精度が高い理由

これまでの評価では、どの特徴量・ラベルでも、窓 2.0 秒のほうが 1.0 秒より精度が高かった。例えば core・SVM では、2.0 秒 0.96 / 0.95 / 0.91、1.0 秒 0.91 / 0.87 / 0.83（flat / step / rough）。

この差が、次のどちらによるのかを確かめた。

- 2.0 秒のほうが本当に分類しやすい。
- 評価の作り方で、2.0 秒が有利になっている（判断の難しい窓が評価から外れる、窓の数が違う、など）。

## サマリ

- **評価の作り方による有利さではない**。中心の時刻が同じで、同じラベルになる窓だけで比べても、1.0 秒 0.91 / 0.87 / 0.82、2.0 秒 0.96 / 0.95 / 0.91 で、差はそのまま残る。段差 ↔ 凸凹の取り違えも、同じ 873 窓で 92 と 39。
- **主な理由は、1 回の判断に使うデータの量**。2.0 秒の窓を前半・後半の 1.0 秒に分けて予測し、SVM のスコアを平均すると、step 0.93・rough 0.92・段差 ↔ 凸凹 49 窓で、2.0 秒（0.95・0.91・39 窓）にほぼ追いつく。
  - 2.0 秒の窓にしか見えない特徴があるのではなく、データが多いほど判断が安定する効果。
  - flat は、平均しても 0.90 で、2.0 秒（0.96）に戻らない。flat では、2.0 秒の窓で計算した特徴量そのものが安定していると考えられる。
- **core の 4 個は、窓が短いと値がぶれる特徴量**。段差 ↔ 凸凹の AUC は、1.0 秒 → 2.0 秒で、z_kurt 0.84 → 0.93、h_crest 0.80 → 0.91、tilt_range 0.73 → 0.88、h_std 0.55 → 0.71。平均をとる z_rms は 0.56 → 0.54 で変わらない。
- **1.0 秒は、ラベルのノイズを受けやすい**。段差・凸凹のラベルなのに窓の中がずっと静かな窓が、1.0 秒で 32%・29%、2.0 秒で 10%・15%。ただし、揺れている窓だけで比べても差は残る（1.0 秒 0.91 / 0.90、2.0 秒 0.96 / 0.95。段差 / 凸凹）。理由の一部で、全部ではない。
- **2.0 秒の評価には、短い段差が入っていない**。段差の通過のうち 15 回は、2.0 秒ではラベルの付く窓ができない。1.0 秒では、その 15 回の窓を 0.91 で当てていて、難しい通過を外して得をしているわけではない。ただ、2.0 秒の窓で短い段差を見落とさないかは、今の評価では測れていない。

## 0. 条件

[rough の再現率が 0.91 にとどまる原因](../2026-11-05/20261105_rough_error_analysis.md)（11.5）と同じ。

| 項目 | 内容 |
| --- | --- |
| データ | 汎用の車椅子・68〜69 kg の 16 セッション（10.31・11.1。step 6・rough 4・flat 6） |
| ラベル | 方針A（区間に窓の半分以上が重なる窓だけを使う）、START を 1 秒後ろにずらす（shift_1） |
| 特徴量 | core（ゼミ資料 131-017）：z_rms・z_kurt・h_std・h_crest・tilt_range |
| モデル・評価 | SVM（標準化 + RBF、C=1.0、`gamma="scale"`、`class_weight="balanced"`）、セッション単位の LOGO。1.0 秒・2.0 秒で同じ設定 |
| 窓 | 1.0 秒・2.0 秒。どちらも窓の長さの 1/4 ずつずらす（0.25 秒・0.5 秒） |
| 静かな窓 | 窓の中で、z の 100 ms RMS 包絡線が、揺れの閾値 7.72 m/s²（汎用の flat 8 セッションの包絡線の 99 パーセンタイル）を一度も超えない窓 |

- 学習とテストはセッション単位で分けている。重なった窓が学習とテストの両方に入ることはない（1.0 秒・2.0 秒とも同じ）。
- 2 章の平均には、SVM の `decision_function` を使った。予測を `decision_function` の最大で決めても、`predict` と 99.7% 以上一致する。

## 1. テストする窓をそろえる

1.0 秒の窓の中心は 0.25 秒ごと、2.0 秒の窓の中心は 0.5 秒ごとにあるので、中心の時刻が同じ窓の組ができる。2.0 秒のラベルのある窓 1713 個は、すべて、中心が同じで同じラベルの 1.0 秒の窓を持っていた。

| テストした窓 | 窓の長さ | flat / step / rough | 段差 ↔ 凸凹 |
| --- | --- | --- | --- |
| それぞれのラベルのある窓すべて | 1.0 秒 | 0.911 / 0.873 / 0.828（3490 窓） | 181 |
| それぞれのラベルのある窓すべて | 2.0 秒 | 0.956 / 0.948 / 0.909（1713 窓） | 39 |
| 中心が同じ 1713 組 | 1.0 秒 | 0.912 / 0.869 / 0.819 | 92 |
| 中心が同じ 1713 組 | 2.0 秒 | 0.956 / 0.948 / 0.909 | 39 |

- 同じ時刻だけで比べても、1.0 秒の精度は、ラベルのある窓すべてのときとほぼ同じ。2.0 秒が、判断の難しい時刻を評価から外して得をしているわけではない。
- 段差 ↔ 凸凹の窓数は、窓の数が違うとそのままでは比べられない（1.0 秒は約 2 倍）。同じ窓でそろえると、92 と 39。

## 2. 1.0 秒の判断を 2 つ合わせる

2.0 秒の窓（start〜start + 2 秒）を、前半（start〜start + 1 秒）と後半（start + 1 秒〜start + 2 秒）の 1.0 秒の窓に分けた。1.0 秒のモデルで、それぞれのスコアを出して平均した。テストする窓は、2.0 秒のラベルのある 1713 個。

| 方法 | flat / step / rough | 段差 ↔ 凸凹 |
| --- | --- | --- |
| 2.0 秒の窓 | 0.956 / 0.948 / 0.909 | 39 |
| **1.0 秒 × 2 のスコアの平均** | 0.899 / **0.927 / 0.919** | **49** |
| 1.0 秒・前半だけ | 0.910 / 0.847 / 0.833 | 99 |
| 1.0 秒・後半だけ | 0.915 / 0.869 / 0.738 | 113 |

- 段差・凸凹は、1.0 秒の判断を 2 つ合わせると、2.0 秒にほぼ追いつく。差の大部分は、1 回の判断に使うデータの量で説明できる。
- flat は、平均すると 0.90 で、どちらか片方だけ（0.91）より少し下がる。2.0 秒（0.96）には戻らない。flat の窓には、継ぎ目などの短い揺れが入ることがあり、1.0 秒ではそれが目立ちやすい。2.0 秒の窓で計算すると、その揺れが薄まると考えられる（確かめてはいない）。
- 後半だけの rough が 0.74 と低いのは、凸凹の区間の終わりの静かな部分（11.5 の STOP 側のずれ）が、後半の窓に入りやすいため。

## 3. 特徴量ごとの分かれ方

1 章の中心が同じ 1713 組で、特徴量ごとに AUC を出した。0.5 から離れているほど分かれる（向きは問わないので、0.5〜1.0）。

| 特徴量 | flat ↔ rough（1.0 → 2.0 秒） | step ↔ rough | flat ↔ step |
| --- | --- | --- | --- |
| z_rms | 0.85 → 0.87 | 0.56 → 0.54 | 0.69 → 0.82 |
| z_kurt | 0.81 → 0.89 | **0.84 → 0.93** | 0.96 → 0.99 |
| h_std | 0.96 → 0.98 | **0.55 → 0.71** | 0.83 → 0.95 |
| h_crest | 0.69 → 0.76 | **0.80 → 0.91** | 0.89 → 0.95 |
| tilt_range | 0.95 → 0.95 | **0.73 → 0.88** | 0.92 → 0.97 |

- z_kurt（尖度）・h_crest（最大 ÷ RMS）・tilt_range（傾きの範囲）は、「窓の中で一番大きな値」や「分布の形」を見る特徴量。窓が短いと、次の 2 つの理由で値がぶれる。
  - 統計的な理由：サンプルが少ないと、尖度などの推定値が不安定になる。
  - 物理的な理由：段差の衝撃は前輪・後輪の 2 回で、車体の傾きも 1〜2 秒かけて変わる（[g_low_high を使う根拠](../2026-11-04/20261104_g_low_high_rationale.md) で、段差の傾きの速さのパワーは 5 Hz 未満に集まっていた）。1.0 秒の窓では、その一部しか入らないことが多い。
- z_rms のように平均をとる量は、step ↔ rough で窓の長さによらない（もともと分かれない）。
- h_std は、step ↔ rough で 0.55 → 0.71 と上がる。1.0 秒では、段差の窓が衝撃を含むか含まないかで値が大きく変わるためと考えられる（確かめてはいない）。

## 4. ラベルのノイズ（静かな窓）

| 窓 | クラス | 窓 | 静かな窓の割合 | 再現率（静かな窓） | 再現率（揺れている窓） |
| --- | --- | --- | --- | --- | --- |
| 1.0 秒 | step | 977 | 32% | 0.80 | 0.91 |
| 1.0 秒 | rough | 813 | 29% | 0.66 | 0.90 |
| 2.0 秒 | step | 465 | 10% | 0.83 | 0.96 |
| 2.0 秒 | rough | 408 | 15% | 0.68 | 0.95 |

- 1.0 秒では、衝撃と衝撃の間や、STOP の前の静かな部分だけの窓ができやすい。2.0 秒の窓は、たいてい揺れのどこかを含む。
- 静かな窓は当たりにくい。そのため、静かな窓が多い 1.0 秒は不利になる。
- ただし、揺れている窓だけで比べても、1.0 秒 0.91 / 0.90、2.0 秒 0.96 / 0.95 で、差は残る。ラベルのノイズは理由の一部。
- 静かな窓が段差・凸凹かは、ボタンの区間の付け方で決まる。ラベルが正確になれば（[ラベルの区間の始まりの決め方](../2026-11-04/20261104_label_interval_eval.md)、11.5 の STOP 側）、1.0 秒と 2.0 秒の差は縮むはず（未確認）。

## 5. 2.0 秒の評価に入らない通過

| 窓 | 段差・凸凹の通過 | ラベルの付く窓が無い通過 |
| --- | --- | --- |
| 1.0 秒 | 205 | 1 |
| 2.0 秒 | 205 | 15（すべて段差） |

- 2.0 秒の窓は、区間に 1 秒以上重ならないとラベルが付かない。START を 1 秒ずらすので、ボタンの区間が約 2 秒より短い段差は、2.0 秒の評価に入らない。
- その 15 回の段差の、1.0 秒の窓（45 窓）の再現率は 0.91。1.0 秒の段差全体（0.87）より高い。2.0 秒が、難しい通過を外して得をしているわけではない。
- ただし、実際に使うときは、短い段差が 2.0 秒の窓の中で薄まり、見落とされる可能性がある。今の評価（方針A）は、区間に半分以上重ならない窓を捨てるので、これを測れていない。

## 6. 考察

| 理由 | 効き方 | 評価の作り方のせいか |
| --- | --- | --- |
| 1 回の判断のデータが 2 倍で、特徴量の値が安定する | 段差・凸凹の差のほとんど（2 章） | いいえ（分類の力の差） |
| 1.0 秒は、静かな窓にラベルのノイズが乗りやすい | 一部（4 章） | 半分はい（ラベルの付け方の問題） |
| 2.0 秒は短い段差を評価していない | 精度は上げていない（5 章） | 評価の範囲が狭いという限界 |

- ゼミで聞かれたら：「2.0 秒のほうが、尖度・クレストファクター・傾きの範囲といった特徴量の推定が安定するため。1.0 秒の判断を 2 つ合わせると、段差・凸凹は 2.0 秒にほぼ追いつくことで確かめた」。
- 2.0 秒の短所は、時間の細かさ（どこで段差があったか）、判断までの遅れ、短い段差の見落としの可能性。アプリで使うときは、窓の長さを、この短所と合わせて決める必要がある。

## 7. 限界

- 1 つの特徴量の組（core）と 1 つのモデル（SVM）で調べた。ほかの特徴量では、窓の長さの効き方が違う可能性がある。
- 2 章の「平均」は、スコアの単純な平均だけを試した。多数決や、重なった 1.0 秒の窓を 4 つ使う方法などは試していない。
- 「静かな窓」は、z の包絡線と 1 つの閾値で決めている。閾値を変えると割合は変わる。
- 各設定 1 回の評価。

