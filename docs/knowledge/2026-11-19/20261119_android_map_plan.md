# アプリで走りながら地図に描く：端末に残る判定結果まで（認識合わせ）

11/10 の企業 MTG で決めた「地図はモバイルアプリで表示する」に着手する前に、`/grill-me` で決めたこと。実装の前に、範囲・完了の判定・非目標をそろえるためのメモ。**状態：合意済み（2026-11-19）。① はエミュレーターで確認済み（下の「① の結果」）。実機での確認は未。**

サーバーの言語（Kotlin か TypeScript か）は、先生の返事待ち（Kotlin 版は `feat/server-kotlin` にプッシュ済みで、`main` には入っていない）。そのため、今回は端末に残る判定結果だけで地図を描き、サーバーから読み出すのは言語が決まってからにする。

## 目的と非目標

- **目的**：実機で走りながら、判定した step・rough がアプリの地図に出ることを確かめる。12/11 の企業の定例のマスト「実際に見える状態」に当たる（11/10 の MTG）。
- **非目標（今回やらない）**
  - サーバーからの読み出し（ほかの人の走行の表示を含む）。
  - PC・Web での閲覧。
  - 続いた窓を区間にまとめること。
  - 凸凹に近づいたときの警告。
  - 利用者によるラベル付け。
  - 本番のサーバーへの送信。

## 完了の判定

- **① の PR**：実機で、画面を消したまま走っても、判定・GPS・記録が続く。送信を切っても判定結果が端末に残り、送信を入れ直すとエミュレーターで今と同じように送れる。`ParityTest` が通ったまま。
- **② の PR**：実機で 1 回以上走り、走行中に地図へ step・rough の点と道の線が増える。アプリを開き直しても、過去の走行が重なる。エミュレーターでは、先に位置を流して、点と線が出ることを確かめる。
- **目安**：11/30。12/11 の定例で見せる。

## ① の結果（エミュレーター、2026-11-19）

`DetectionService`（フォアグラウンドサービス、種類は位置）に、判定・GPS・記録・送信を移した。画面（`MainActivity`）は、`LiveStatus` で様子を受け取って出すだけにした。送信のオン・オフは `UploadSettings`（既定はオン）。エミュレーターは Pixel 7・API 37。サーバーは `main` の TypeScript 版。

| 確認 | 結果 |
| --- | --- |
| 単体テスト（`ParityTest` を含む） | ○ 20 件 |
| 1. 送信オン、40 秒。始めて約 6 秒でホーム画面に戻り、画面を消す | ○ 75 窓。窓の間隔はすべて 500 ms、サンプルの間隔は最大 10 ms で、画面を消したあとも途切れない。端末・DB・S3 で一致（欠け 0・余り 0、生データの sha256 も一致） |
| 2. 送信オフ、20 秒 → オンに戻す | ○ オフの間は、走行の登録も送信も無し（DB 0 件）。端末に 36 窓が残る。オンに戻すと、36 窓と生データが送られ、一致 |
| 3. 走行中に、送信を切って入れ直す | ○ 切っている間は、端末に 29 窓、送れたのは切る前の 8 窓。入れ直すと 56 窓すべて送られ、二重も無し |
| 4. 権限を外して起動 → 拒否 → 「判定を始める」 → 許可 | ○ ボタンで権限をもう一度求め、許可すると待たせていた走行が始まる |
| 5. 通知の「止める」 | ○ 走行が止まり、残りを送ってサービスが終わる。65 窓が一致 |
| lint | ○ エラー無し。今回のコードの警告（SDK の版の分岐、wake lock の上限、スイッチの部品）は直した |

**途中で直したこと**：adb から起動の指定（`--ei live_s` など）を送ると、作り直された画面が前の起動の指定を読み直し、走行をもう 1 回始めていた。画面を作り直したときは指定を処理しないようにした。開いている画面に届いた指定は `onNewIntent` で処理する（`launchMode` を `singleTop` に）。ボタンで操作するときには起きない。

**分かったこと**
- エミュレーターのセンサーは 100 Hz（窓のサンプルは 200）。11/18 の走行も 100 Hz だったので、サービスに移したことによる変化ではない。実機では約 333 Hz になるはず（計測用アプリと同じ設定）。
- 位置が付くのは、走り始めの数窓を除いた分（75 窓のうち 70 窓）。GPS の最初の位置が届くまでの窓には付かない（前と同じ）。
- 走行中は、画面を自動で消えないようにする設定（前の Activity にあった `FLAG_KEEP_SCREEN_ON`）をやめた。画面を消して使うため。

**まだ確かめていないこと（実機）**：画面を消してポケットに入れたまま走ったときに、判定・GPS が続くか（機種によっては、電池の節約でセンサーが間引かれることがある。推測）。実際のサンプリングの速さと電池の減り方。

## 調べたこと

Google マップ（Maps SDK for Android）の料金と登録（2026-11-19。どのページにも更新日の記載はなかった）。
- **表示**：「All mobile usage of the Maps SDK for Android is unlimited」。アプリで地図を出すのは、回数無制限で無料。マーカーや線に別の料金の項目は見当たらなかった。ただし、線（polyline）についてはどのページにも記述が無く、マーカーについての記述も JavaScript 版の文脈のもの（[Usage and Billing](https://developers.google.com/maps/documentation/android-sdk/usage-and-billing)、[料金の一覧](https://developers.google.com/maps/billing-and-pricing/pricing)）。
- **登録**：「you must have a billing account, and all requests must include a valid API key」。課金アカウントを付けないと「1 request per day」に制限される（[FAQ](https://developers.google.com/maps/faq)）。
- **PC で見る場合**（今回は非目標）：Web 版の Dynamic Maps は、月 10,000 回までが無料で、超えると 1,000 回あたり $7。

## 残る未確定

- **地図の土台**：Google か OSM か。先生の返事で決める。
- **OSM の部品とタイル**：MapLibre などのどれを使うか、タイルをどこから取るか。実装に入るときに、OSM のタイルの利用規約（出典の表示、まとめて取得しないことなど）を確かめて決める。
- **送信の既定値**（推測）：既定はオンにして、エミュレーターでの開発は今と同じ動きにする。実機では画面から切る。
- **実機の機種と Android の版**：Android 14 以降では、フォアグラウンドサービスの種類（位置情報など）を宣言する必要がある。どの版でも動くように作る。
- **ブランチ**：① は `feat/android-client` で作る。② は ① をマージしてから、新しいブランチを切る。
