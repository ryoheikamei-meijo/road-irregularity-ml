# 性質の違う特徴量を 1 種類ずつ足す（後ろ固定のみ、10.3 + 10.4、バーストなし）

第16回ゼミ（10.13）の後、データ収集の前に、今のデータのまま特徴量を工夫するとどこまで上がるかを確認した。今の特徴量（基本4 + 尖度・クレスト）に、性質の違う特徴量を 1 種類ずつ足し、どれが効くかを見た。対象は z 軸のみ（z6）・3 軸（xyz18）・合成（m6）の 3 つ。

## サマリ

- **step と rough の区別（間違いの 65% を占める部分）を上げる特徴量は、今回も見つからなかった**。どれを足しても、step と rough だけの 2 クラス精度は ±0.01 以内か、下がる。
- **帯域パワー比**は、3 クラスの精度が上がる（2.0 秒・xyz18 で SVM 0.861 → 0.872、RF 0.811 → 0.849）。ただし、上がるのは **step を flat と見逃す窓が減った**ため（SVM 28 → 12 窓、RF 16 → 2 窓）。代わりに rough を step と間違える窓が増え（SVM 36 → 54）、step と rough の区別は下がる（0.845 → 0.797）。10.6 の帯域パワー（絶対値）と同じ傾向。
- **ピーク数・閾値超過時間率**は、1 個だけで見ると step と rough をよく分ける（z 軸のピーク数の AUC は 0.880 で、`z_rms` の 0.798 より高い）。それでも、足したときの差は ±0.01 程度で、誤差の範囲。`rms` との相関が 0.91〜0.94 と高く、**基本4 と同じ「揺れの大きさ」の情報になっている**ため。
- **スペクトルエントロピー**は、xyz18 の 2.0 秒だけ少し上がる（SVM +0.013、RF +0.024）。z6 と 1.0 秒では下がる。上がり方は、帯域パワー比と同じく step → flat が減ったため。
- **自己相関**は、ほとんどの構成で下がる（−0.02 前後）。
- **積み上げても伸びない**。最も良いのは xyz18・2.0 秒・SVM で、帯域パワー比 1 種類を足した 0.872（+0.011）。それ以上足しても、上がらないか下がる。
- 軸の構成の違い（z6 < m6 < xyz18）は、どの特徴量を足しても変わらない。

RF のシードを変えたときのばらつきは ±0.003〜0.004（標準偏差）。ただし、これにはデータの分け方のばらつきが入っていないので、**±0.01〜0.02 の差は、これまでどおり誤差として読む**。

### 足した特徴量

ベースと同じ軸ごとに計算した（xyz18 なら 3 軸分）。x は窓の中の信号（z 軸は重力を引いたもの、合成は |a| − g）。

| グループ | 特徴量（軸ごと） | 中身 |
| --- | --- | --- |
| `peaks` | 1 個 | ピーク数（1 秒あたり）。\|x − 窓平均\| が閾値 θ を超える極大の数。ピーク間の最小間隔は 50ms |
| `tat` | 1 個 | 閾値超過時間率。\|x − 窓平均\| > θ のサンプルの割合 |
| `band_ratio` | 5 個 | 帯域パワー比（帯域のパワー / 直流を除く全体のパワー）。帯域は 10.6 と同じ 0.5–10 / 10–30 / 30–60 / 60–100 / 100Hz– |
| `spec_entropy` | 1 個 | スペクトルエントロピー（0〜1） |
| `acf` | 2 個 | 自己相関のピーク値とラグ [s]。自己相関が最初に負になってから、窓の半分までで探す |

- **θ**：fold ごとに、**学習データの flat の窓だけ**から μ + 3σ（\|x − 窓平均\| の全サンプル）で決めた。テストの情報は使っていない。2 クラス評価では flat はテストに入らないので、全 flat の窓から決めた。値は z で約 10.9、合成で約 9.7、x・y で約 6.8〜7.7 m/s²（flat の振幅の上位 1% 程度）。
- 入れなかったもの（進め方の提案どおり）：ジャーク最大値（`diff_max` と同じもの）、エネルギー集中率・インパルスファクター・波形率（尖度・クレストと似ている）、スペクトル重心・ゼロ交差率（帯域パワー比と重なる、10.6 で flat だけに効いた）、歪度・パーセンタイル・IQR（10.6 で効かなかった）、ピッチ角速度（ジャイロがない。姿勢のクォータニオンは約 5Hz でしか更新されない）。

## 3. ピーク数が効かない理由

1 個だけで step と rough を分けられるか（AUC、2.0 秒窓）と、`rms` との相関を見た。AUC は 0.5 から離れるほど分けられる（0.5 未満は向きが逆で、rough のほうが小さい）。

| 特徴量 | AUC（rough と step） | `rms` との相関 |
| --- | --- | --- |
| `z_peak_rate` | **0.880** | 0.91 |
| `z_tat` | 0.840 | 0.94 |
| `z_rms` | 0.798 | 1.00 |
| `z_kurt` | 0.124（逆向きに 0.876） | −0.41 |
| `z_br_10_30` | 0.378 | −0.15 |
| `z_spec_entropy` | 0.577 | 0.13 |
| `m_peak_rate` | 0.877 | 0.87 |
| `m_spec_entropy` | 0.813 | 0.06 |

- **ピーク数は、1 個だけで見ると、z 軸の今の特徴量（`z_kurt`・`z_rms`）と同じか、それ以上に分ける**（表で比べたのは、この表の特徴量だけ）。平均も step 3.1 回/秒、rough 9.1 回/秒（z 軸）と大きく違う。
- それでも足して上がらないのは、**`rms` との相関が 0.91 と高い**ため。θ を固定した閾値なので、揺れが大きい窓ほどピークが多く数えられ、結局「揺れの大きさ」を数え直していることになる。閾値超過時間率も同じ（相関 0.94）。
- 尖度は、`rms` との相関が −0.41 と低く、別の情報を持っている。今の基本4 + 尖度の組み合わせで、ピーク数の持つ情報は、ほぼ表せていると考えられる。
- 帯域パワー比は、`rms` とはほぼ無相関（−0.15）で、新しい情報を持つ。ただし、その情報は step と flat を分ける方向に効き、step と rough は分けない。

## 4. まとめと考察

- **今のデータでは、メモの特徴量を足しても、step と rough の区別はほぼ上がらない**。3 クラスの精度は最大 +0.01〜0.04 上がるが、上がるのは「段差を平坦と見逃す」窓が減った分。
- 3 クラスの精度を上げたいだけなら、**帯域パワー比**が一番効く（とくに RF）。step の見逃し（step → flat）を減らす目的で使うのは、ありうる。ただし、flat は 1 セッションしかなく、速度の違いを拾っている可能性があるので、flat を追加計測してから判断したほうがよい（10.6 と同じ注意）。
- 「単発の衝撃か、続く揺れか」は、ピーク数で表せるが、今の特徴量でもう表せている。step と rough の取り違えが残るのは、特徴量で表せる情報が足りないというより、**ラベルの粗さ（10.12 の 3 章：区間の入り口の窓、衝撃を含まない step の窓）や、間違いが集中している 3 セッションの影響が大きい**可能性がある。→ 波形で確かめた結果は [step と rough の取り違えの原因](20261017_step_rough_error_causes.md)。rough → step はラベルの粗さ、step → rough は 2 つの step セッションの揺れ方の違いが原因だった。
- ゼミの「z と x・y のどちらが大事か」に対して：z だけ（z6）は、何を足しても xyz18・m6 より低い（2.0 秒 SVM で 0.822 対 0.861）。z だけでは足りず、水平方向の情報が効いていることは、特徴量を足しても変わらない。
- 次の候補：
  - θ を窓の大きさに合わせる（例：窓の rms の何倍か）と、ピーク数が「揺れの大きさ」から切り離されて、別の情報になるかもしれない。10.5 のバーストの `n_peaks` はこの形（窓の最大の 30%）で、ベースに足すと step → flat を減らしていた（10.12 の 3 章）。
  - 特徴量よりも、データ（step と rough のセッション数、flat の追加）を増やすほうが効く可能性が高い。

### 限界

- 各設定 1 回の評価（RF のシードのばらつきは ±0.004 程度だが、データの分け方のばらつきは見ていない）。
- 帯域の区切りや θ（3σ）、ピーク間の最小間隔（50ms）は 1 通りしか試していない。
- 積み上げの順番は、同じデータの結果から決めている。

## 5. 再現方法

後ろ固定のみのデータディレクトリを作る（10.5 の 9 章と同じ。作る場所はどこでもよい）。

```bash
mkdir -p /tmp/rear_only
for d in wheelchair_data/10.3/2026* wheelchair_data/10.4/2026*; do
  n=$(basename $d)
  case $n in 20261004171104|20261004171723) continue;; esac
  ln -sfn "$PWD/$d" /tmp/rear_only/$n
done
python -m src.scripts.evaluate_added_features --data-dir /tmp/rear_only
```

- `--step single cumulative noise` で、1 章（1 種類ずつ）・2 章（積み上げ）・RF のシードのばらつきを選べる（既定は全部、約 10 分）。
- 出力は `data/analysis/20261017_added_features/`：`single_sweep.csv`（1 章）、`cumulative_sweep.csv`（2 章）、`rf_seed_noise.csv`（シードのばらつき）。
- 3 章の AUC と相関は、スクリプトには入れておらず、その場で計算した。
