# 2026/10/17 加速度の軸の扱い：鉛直は世界座標系の z、水平は x・y の大きさを使う

## Status

- accepted

## Situation

- 研究は 1 人で進めている。データは、10.3・10.4 に同じ場所で測定した後ろ固定の 12 セッションのみ（step 7、rough 4、flat 1）。
- スマホは、マウントで車椅子の後方にがっちり固定している。ただし、固定するスマホの位置・向きには、付ける人や日によって差が出る（10.3 と 10.4 でも、付け方の向きが変わっていた可能性が高い）。
- 今後は、新しく買った車椅子での測定や、いろいろな道（北向き・東向きなど、走る向きが違う道）での測定を予定している。
- 収集アプリ（`MyApplication3`）は、生の加速度（端末の座標系）と姿勢（rotation vector）を記録している。2026/10 に、姿勢の登録レートを上げ、ジャイロ・重力を除いた加速度・地磁気を使わない姿勢（game rotation vector）も記録するように変更した。

## Context

- 今の前処理は、加速度を世界座標系（x = 東、y = 北、z = 上）に変換し、x・y・z の 3 軸（xyz18）で特徴量を作っている。変換の目的は、スマホの付け方の個人差を補正することだった。
- ところが、世界座標系の x・y は東・北に固定されるので、**車椅子が走る向きが変わると、同じ揺れでも x と y の中身が入れ替わる**。付け方の差のうち、傾き（前後・左右の傾き）は補正できるが、水平の向き（水平面内の回転）は補正できない。
- 第 16 回ゼミ（10.13）で、「x・y が効いているが、z が大事だと思っていたがどうなのか」という指摘があった。x・y の効きが、走る向きに依存した見かけのものではないかを確かめる必要があった。
- いろいろな道を走るデータで使うには、走る向きに依存しない軸の扱いを決めておく必要がある。

## Material for decision

- [世界座標系の x・y は、走る向きに依存するか](../knowledge/2026-10-17/20261017_heading_dependence.md)（10.17）
  - 走る向きは、セッションごとに最大約 115° 違っていた。水平の揺れの主な向きも、10.3 はほぼ東西、10.4 はほぼ南北で、車体の同じ方向の揺れが、日によって x（東）と y（北）に分かれて入っていた。
  - テストのセッションだけ x・y を 90° 回転させると（別の向きに走った場合の想定）、xyz18 の精度は落ちる（2.0 秒窓で SVM 0.861 → 0.835、RF 0.811 → 0.767。1.0 秒窓の RF では 0.762 → 0.669、flat の再現率 0.78 → 0.52）。
  - x・y を水平の大きさ √(x² + y²) に置き換えても、精度は落ちない（2.0 秒窓で SVM 0.861 → 0.876、RF 0.811 → 0.824、step と rough の区別 0.845 → 0.862。1.0 秒窓では SVM 0.832 → 0.824 で誤差の範囲）。
  - 前後・左右に分けた軸（水平の揺れの主軸から推定）は 0.844 で、水平の大きさより良くならなかった。
  - z だけ（z6）は 0.822 で、水平の情報も効いている。
- [特徴量の寄与度・窓幅・誤分類の内訳](../knowledge/2026-10-12/20261012_feature_importance_no_burst.md)（10.12）：x・y 軸の効きは走行方向に依存する可能性がある、という注意。
- Android の公式ドキュメント（sensors_motion、AOSP の sensor-types）：世界座標系の加速度を直接出すセンサーはなく、姿勢（rotation vector）を使ってアプリ側で変換する必要がある。rotation vector は地磁気を使い、game rotation vector は地磁気を使わない（Y は北を向かない）。

## Decision

加速度の軸は、次の 2 つで表す。今後の解析の基本の構成を、xyz18 から **zh12（z + 水平の大きさ、それぞれ基本4 + 尖度・クレストの 6 種類）**に切り替える。

```
生の加速度（端末の座標系）─(姿勢で世界座標系に変換)→ x, y, z
                                                      ├ z − g        … 鉛直の揺れ
                                                      └ √(x² + y²)   … 水平の揺れの大きさ
```

1. **鉛直は、世界座標系の z から重力を引いたもの（z − g）を使う。**
   - 理由：スマホをどう傾けて付けても、z は鉛直になる。付け方の傾きの差を補正できる。
2. **水平は、世界座標系の x・y を合成した、水平の大きさ √(x² + y²) を使う。x・y を個別には使わない。**
   - 理由：水平の大きさは、水平面内でどの向きを向いていても同じ値になる。走る向きにも、スマホの水平の向きの付け方にも依存しない。今のデータでは、x・y を個別に使うより精度が同じか少し良い。
   - 水平の大きさは、世界座標系に変換したあとの x・y から計算する。変換前の端末の x・y で計算すると、傾きによって重力の成分が混ざるため。
3. **世界座標系への変換は、これまでどおり後処理（解析側）で行う。** 収集アプリは、生の加速度と姿勢を記録する。
   - 理由：生の値と姿勢を残しておけば、変換の方法を後から変えられる。
4. 呼び方：3 軸の大きさ |a| − g（これまでの「合成」、m6）と区別するため、√(x² + y²) は「**水平の大きさ**」（軸名 `h`）と呼ぶ。

## Consequences

### 良い面

- 走る向きが違う道のデータでも、同じ特徴量で学習・評価できる。
- スマホの付け方の差（傾き・水平の向き）の影響を受けない。新しい車椅子や、付ける人が変わっても使いやすい。
- 特徴量の数が 18 個から 12 個に減る。
- 東・北の向きが不要になるので、地磁気を使わない姿勢（game rotation vector）でも変換できる可能性がある。地磁気を使わなければ、車椅子の鉄のフレームの影響も受けない（新しいデータで、rotation vector と比べて確かめる）。

### 受け入れたトレードオフ

- **前後の揺れと左右の揺れを区別できなくなる**。段差では前後方向の衝撃が特徴的な可能性があるが、その情報は水平の大きさに混ざる。今のデータでは、前後・左右に分けても精度は上がらなかったので、受け入れる。
- 10.12・10.17 までの結果（xyz18 での「x 軸が効いている」など）は、「水平の揺れが効いている」と読み替える必要がある。発表資料の数値は xyz18 のままなので、比較するときは注意する。
- 水平の大きさは 0 以上の値なので、`kurt`・`crest` などの形の特徴量は、x・y のときとは意味が少し変わる。
- 姿勢（rotation vector）の精度に、z と水平の大きさの分離が依存する。2026/10 以前のデータは、姿勢が約 5Hz でしか更新されていない。

### 今後、見直す条件

- 前後・左右を区別したほうが良いことが分かった場合は、車体座標系（前後・左右・上下）への変換を検討する。そのときは、計測の最初に「止まった状態で数秒」「まっすぐ前に押し出す」を入れて、前後の向きを決める方法を考える。
