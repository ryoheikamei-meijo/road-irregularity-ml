# 10.3 / 10.4 データの分析結果と、次の測定でやること

## 1. 背景・目的

10.3 以降のデータは、サンプリング周波数を約 334Hz に上げて収集している（それ以前の 6.22 / 7.12 は約 4Hz で別物のため、今回の分析には使っていない）。アプリ側も、通常の段差・凸凹ボタンとは別に、行ったり来たりする区間用の「継続」ボタン（`dansa_cont_*` / `dekobo_cont_*`）を追加した。

本メモは、10.3 と 10.4 の分析で分かったことと、そこから導いた「次の測定でできること」をまとめる。

## 2. 使ったデータ・条件

| 項目 | 内容 |
| --- | --- |
| データ | `wheelchair_data/10.3`（実在 8 セッション）+ `wheelchair_data/10.4`（6 セッション） |
| flat | `wheelchair_data/10.4/20261004172306` のみ（継続フラグなし、平坦のみを走行） |
| step / rough | `*_cont_start`〜`*_cont_stop` の区間にかかる窓。区間外の窓は学習にも評価にも使わない（方針A） |
| 窓 | 1.0 秒・刻み 0.25 秒（窓幅は 0.1〜2.0 秒で比較した） |
| ラベル付け | 窓とイベント区間の重なり比率が 0.5 以上。イベント開始の 0.5 秒前から含める |
| 時刻合わせ | イベントの `elapsed_ms` は `acc.csv` の `elapsed` より約 0.24 秒ずれるため、壁時計の `timestamp` で合わせた |
| 評価 | セッション単位CV（Leave-One-Group-Out）。flat は 1 セッションのため、時間方向に 5 ブロックへ分け、境界から窓幅以内の窓を捨てて擬似グループにした |

行数ベースの比率（イベント区間の内外で分けたもの、10.3 + 10.4）は、平坦 22.7%・段差 40.7%・凸凹 36.7%（14 セッション）。ただし、flat の大半は 10.4 の平坦のみセッション 1 つである。

## 3. 分析でわかったこと

### 3.1 走行中の flat は揺れが大きい

10.3 だけで評価すると、flat（イベント区間外の窓）は低い値にまとまって分離できていた。10.4 の平坦のみセッションを加えると、flat は step と大きく重なった。

![z軸基本4特徴量（10.3+10.4）](../../data/analysis/20261004_boxplot_103_104/figures/three_class_feature_distributions.png)

区間外の窓は、開始直後・終了直前の静止寄りの状態が多いと考えられ（速度で厳密には確認していない）、実際の平坦走行の振動とは条件が違う。平坦のみセッションの z 軸は、1 秒窓の最大・最小で約 ±12 m/s²、標準偏差の中央値は約 3.8 あった。

![平坦のみセッションの z 軸波形](../../data/analysis/20261004_boxplot_103_104/figures/waveform_20261004172306.png)

窓内の最大・最小の振れだけでは、flat と event の分離は不十分だった（flat 窓の |z| 最大の 95% 点を閾値にすると、event 窓の検出率は 59.5%（rough 78%、step 43%）、AUC は 0.73）。

![窓内の最大・最小の比較](../../data/analysis/20261004_boxplot_103_104/figures/peak_flat_vs_event.png)

スマホを車椅子に取り付けているため、走行中は常に取り付け由来の振動が乗る可能性があり、全軸に共通の「床」ができていると推測している（未検証）。

### 3.2 flat / step / rough の波形の違い

代表セッション（flat: `20261004172306`、step: `20261004170739`、rough: `20261004171557`）を縦軸共通で並べた。

![z軸の比較](../../data/analysis/20261004_boxplot_103_104/figures/comparison_z.png)

- flat: 小さい振幅の連続的な振動が一定に続く。
- step: 約 4 秒おきに鋭いバースト（最大 ±50〜57 m/s²）が単発で出て、間は静か。
- rough: 大きな振動が数秒のまとまりで続く。

step は「静かなベース＋短い強いバースト」、flat は「中くらいの振動が一定」で、窓全体の標準偏差のような平均的な振幅では分けにくい。

### 3.3 評価結果（方針A、セッション単位CV）

特徴量は z 軸基本 4 種（`z_std`・`z_range`・`z_rms`・`z_diff_max`）、または 3 軸分の基本 4 種（12 個）。尖度・クレストファクターは窓内の波形の形を表す特徴量で、バーストが入る窓で大きくなる。

| 特徴量 | モデル | 0.5秒 | 1.0秒 | 2.0秒 |
| --- | --- | --- | --- | --- |
| z4 | SVM | 0.679 | 0.720 | 0.777 |
| z4 | RF | 0.510 | 0.595 | 0.639 |
| z4 + 尖度 + クレスト | SVM | 0.722 | 0.762 | 0.798 |
| z4 + 尖度 + クレスト | RF | 0.573 | 0.691 | 0.770 |
| xyz12 | SVM | 0.706 | 0.722 | 0.772 |
| xyz12 | RF | 0.611 | 0.670 | 0.743 |
| xyz12 + 尖度 + クレスト | SVM | 0.730 | 0.747 | 0.789 |
| xyz12 + 尖度 + クレスト | RF | 0.679 | 0.743 | **0.827** |

（数値は balanced accuracy。窓数は 1.0 秒で flat 267・step 871・rough 785）

- 尖度とクレストファクターを足すと、ほぼ全ての組み合わせで精度が上がった。特にバーストの形が関わる step の再現率が上がった。
- 80% 台に届いたのは、2.0 秒の xyz12 + 尖度 + クレスト（RF）の 1 つだけ。窓数が少なく、設定を多数比較した最良値のため、割り引いて見る必要がある。
- flat は 1 セッションを時間分割しただけなので、別の日・路面でこの精度が出る保証はない。

### 3.4 誤りの種類は 2 つある

最良設定（2.0 秒、xyz12 + 尖度 + クレスト、RF）で、step と rough は両方向に同程度混ざる（rough → step 15%、step → rough 12%）。誤り窓を波形に重ねて確認した（下段の緑が正解、赤が誤り。目視した 3 セッションの印象であり、全体の割合は数えていない）。

**① rough → step の誤り（ラベルの粗さが原因とみられる）**

行ったり来たりの区間内には、振動が小さい部分（山の端や間）があり、そこも rough ラベルのままになっている。静かな窓は、特徴量上は rough に見えず step と判断される。

![誤分類窓: 20261003170139（rough）](../../data/analysis/20261004_boxplot_103_104/figures/misclassified_20261003170139.png)

**② step → rough の誤り（特徴量・窓の設計が原因とみられる）**

バーストが近接する場所や、バーストの後に余韻が長く続く場所で、窓内に複数のバーストと尾が入り、連続した振動（rough）と区別できなくなる。

![誤分類窓: 20261003172637（step）](../../data/analysis/20261004_boxplot_103_104/figures/misclassified_20261003172637.png)

![誤分類窓: 20261004172046（step）](../../data/analysis/20261004_boxplot_103_104/figures/misclassified_20261004172046.png)

## 4. 次の測定でできること

### 4.1 平坦のセッションを追加する（最優先）

- 現状、flat は平坦のみのセッション 1 つだけで、評価の信頼性が低い。
- 速度（遅い・普通・速い）と路面（アスファルト、タイル、ブロックなど）を変えて、継続ボタンを押さない通常走行を、あと数セッション取る。
- 平坦のみのセッションは、1 回を長くするより、セッション数を増やす方が、セッション単位の評価で効く。
- 取り付け振動（3.1 の推測）を確かめるため、端末の固定方法を変えた平坦走行も、可能なら 1 セッション取る。

### 4.2 通過ごとの正確なラベルを取る（① の対策）

- アプリの通常ボタン（`dansa_start/stop`、`dekobo_start/stop`）を使い、障害物を渡る間だけ押す。区間内に平坦走行が混ざらず、加速度と独立した正確なラベルになる。
- 継続ボタンは、連続して渡る区間に限る、という使い分けにする。
- 通過ごとのラベルと継続区間のラベルを同じ場所で取れば、継続区間のラベルの粗さがどれくらい影響しているかも確かめられる。

### 4.3 ジャイロ（角速度）を記録する

- 現在のアプリは、加速度と回転ベクトルしか登録していない（`TYPE_GYROSCOPE` は未使用）。回転ベクトルは約 5Hz で更新されるため、衝撃の最中の角速度は取れない。world 座標への変換にも、5Hz の姿勢を使っている。
- 段差では、キャスターの乗り上げや後輪の落下で、車体のピッチが瞬間的に変化するため、角速度に特徴が出る可能性がある。flat vs event の分離に効くかは未検証。
- アプリに `TYPE_GYROSCOPE` を追加し、`acc.csv` に角速度の列を足す。サンプリングレートは、加速度と同じ水準（端末の上限、約 334Hz）にそろえる。
- まず平坦と段差を少数セッション取り、角速度の最大値・RMS・ピーク幅を箱ひげ図で比べて、効きそうかを確認してから本格的に収集する。

### 4.4 収集の条件をそろえて記録する

- 速度が振動の大きさに効いている可能性がある。平坦のみのセッションは平均 0.91m/s で、step のセッション（0〜0.65m/s）と条件が違い、交絡している。
- 平坦と、step・rough を、同じ速度帯で取る。難しければ、速度（`speedMps` は GPS で約 1 秒更新と粗い）と合わせて、走行の速さの目安を別にメモしておく。

### 4.5 イベント種別ごとのセッション数

- 段差・凸凹のセッションは、10.3 + 10.4 で段差 8・凸凹 5。行数は十分だが、独立なセッション・障害物の数が少ない。
- 障害物の種類・高さ・進入角度・速度・乗員の体重を変えて、セッション数を増やす。評価用に、学習に使わない日・場所のデータを別に確保できるとよい。

## 5. 今のデータでできる分析（実施済み）

下記の 2 つは実施した。結果は [20261004_analysis_log_103_104.md](./20261004_analysis_log_103_104.md) の 10 章を参照。

- **バーストの数・間隔を特徴量にする（② の対策）**: 窓内でピークを検出し、その数、ピーク間隔、包絡線の突出度と時間割合を特徴量にした。精度は 1〜3 ポイント上がった（窓 2.0 秒の最良で balanced accuracy 0.844）。step → rough の誤りは減ったが、rough → step は変わらなかった。
- **区間単位で評価する（① の対策）**: 窓ごとの予測を、セッション単位と 8 秒チャンク単位で多数決した。精度は大きく上がるが（セッション単位 1.000、8 秒チャンク 0.987）、問題が易しくなっていて、強い証拠にはならない。
- 閾値でラベルを付け直す案は、閾値に使った特徴量と同じ特徴量で学習・評価すると循環になり、数字が実力より高く出るため、評価には使わない（使うなら参考値）。

## 6. 注意点

- 評価は設定ごとに 1 回で、ばらつき（シードや分割による差）は見ていない。窓幅・特徴量を多数組み合わせて選んだ最良値には、選択バイアスがある。
- flat のブロック分割は、同じ走行を学習側と評価側に分けているため、flat の再現率は甘く出ている可能性がある。
- 「取り付け振動が床を作っている」「静かな窓が step に見える」は、波形と数値からの推測で、検証していない。

## 7. 再現方法

データ（10.3 と 10.4）を 1 つのディレクトリに並べた上で、以下を実行する（引数 `--data-dir` にそのディレクトリを渡す）。出力先は `data/analysis/20261004_boxplot_103_104/`（`--output-dir` で変更可）。

| 目的 | スクリプト |
| --- | --- |
| 窓特徴量と、z軸・ジャークの箱ひげ図 | `src/scripts/plot_boxplots_103.py` |
| z軸加速度（サンプル単位）、x・y軸の箱ひげ図 | `src/scripts/plot_boxplots_103_extra.py` |
| 窓内の最大・最小の比較（flat vs event） | `src/scripts/analyze_peak_flat_vs_event.py` |
| セッション単位の波形 | `src/scripts/plot_session_waveform.py`（`--axis` で x/y/z） |
| flat / step / rough の波形比較 | `src/scripts/plot_session_comparison.py` |
| 方針Aの評価（窓幅の比較） | `src/scripts/evaluate_103_planA.py` |
| 尖度・クレストファクターを足した評価 | `src/scripts/evaluate_103_shape_features.py` |
| 誤分類窓の波形への重ね描き | `src/scripts/plot_misclassified_windows.py` |
| ベースライン評価 / 窓幅スイープ / 混同行列 | `evaluate_103_baseline.py` / `evaluate_103_window_sweep.py` / `confusion_103_shape.py` |

実行は `python -m src.scripts.<スクリプト名>` の形式。評価結果の表は `planA_sweep.csv`、`shape_features_sweep.csv`、窓ごとの特徴量は `shape_features_windows_1s.csv` などに保存されている。
